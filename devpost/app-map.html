What Else? App Map

A snapshot of how the app fits together, taken from commit ebfa097 on 25 Oct 2026. The code can drift from this page after later changes.

What it is

A local web app. You describe a challenge, and five creative agents (Reverse Thinking, Random Associations, Analogies, SCAMPER, Challenging Assumptions) build on each other's ideas to produce about 10 possibilities. Your reactions are stored and fed into the next round, along with your own ideas, experiments and their outcomes. Everything runs on your computer, and the agents run through Claude Code on your existing subscription, with no API key.

Web pages

web.py plus templates/. FastAPI routes return HTML, and HTMX swaps in just the part of the page that changed.

Rules and history

service.py makes every change: one event plus the status update, saved together. Stored in models.py (SQLite).

Learning boundary

context.py decides what history the agents see: what you tried, liked, rejected and reworked.

Agents

orchestrator.py runs patterns/collaborative.py. Prompts are in prompts/ and techniques in techniques/. llm.py is the only file that calls Claude.

One action, end to end: clicking Generate

Reference route: three stops

A reference route for later. It wasn't walked through as a tour; search your editor for the names shown.

1
src/whatelse/web.py, def generate

The route the Generate button posts to. It calls the agents, turns any failure into a friendly message ("The agents couldn't finish…", or "already working" if you click twice), and returns the refreshed tabs.

2
src/whatelse/orchestrator.py, def run_generate

Refuses if a run is already going or the challenge is paused or closed, records a GenerationRun, asks context.build_context for your history, runs the pattern, then saves all ideas plus their idea_created events together.

3
src/whatelse/patterns/collaborative.py, def run

The core of the app. Round 1 (def round1): each agent names the obvious moves, which become the banned list, and proposes 3 wild seeds. Round 2 (def round2): each agent makes 2 ideas, each fusing seeds from at least two other techniques. Round 3 (def round3, _assign_pushes): each idea is pushed further by a different agent. The code, not the model, works out which techniques get credit.

A practice to reuse: measure the agents, then change them

What happened. The first two-round version worked, but felt "not super creative". Instead of tweaking prompts blind, the build measured it. The run data showed only 1 of 5 agents had actually built on another agent's seed, and replaying one logged call showed that thinking effort, not the number of calls, caused the slowness (low about 20s, medium about 106s, default about 123s).

Evidence. devpost/checklist.md → Revisions. The pattern now records fused_two_techniques per draft, and python -m whatelse.try prints "Drafts fusing two or more other techniques: N/10". The redesigned pattern scored 10/10 on a sample run, at about 125s with effort set in config.toml.

Reuse it. When a multi-agent system disappoints, make the collaboration observable first: log every call, store intermediate outputs (seeds, drafts, who built on what), and put one number on the behaviour you want. Then change one thing and compare against that number. The terminal try command and the JSONL call log are the cheap tools that made this possible.

Running it again

  • Everyday use: double-click What Else.cmd (or the desktop shortcut). If the app is already running, it just opens the browser. If an older copy is running, it replaces it.
  • From a terminal: .venv\Scripts\python -m whatelse, then open http://127.0.0.1:8000.
  • Agents only, no web app: .venv\Scripts\python -m whatelse.try "your challenge" --context "optional"
  • Tests (they use a fake agent and never call Claude): .venv\Scripts\python -m pytest
  • Your data lives outside the project in %LOCALAPPDATA%\WhatElse\ (whatelse.db and logs/agent-calls.jsonl), so it can't be committed.
